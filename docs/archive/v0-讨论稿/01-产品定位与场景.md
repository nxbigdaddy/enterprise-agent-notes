# 01 · 产品定位与场景

> 版本：v0.1（草稿）

## 1. 定位

**公司内部统一的 AI 办公入口。**

三个关键词：

- **统一入口**：员工不再需要在十几个系统、无数个 AI 网页之间切换，一个助手覆盖日常办公。
- **能力平台**：IT 提供底座与治理，业务部门可以在平台上定义自己的技能与流程。
- **可执行的助手**：不仅能回答，还能读邮件、写文档、查数据、跑流程、动本机文件——所以必须配套治理。

反面定位（我们**不是**什么）：

- 不是一个套壳的 ChatGPT 网页。
- 不是给每个部门各自买一套 SaaS 工具。
- 不是把人替换掉的自动化流水线（在 P1/P2 阶段不是）。

## 2. 用户角色

| 角色 | 谁 | 关心什么 | 关键诉求 |
|---|---|---|---|
| **普通员工** | 全员 | 少干活、少出错 | 上手即用、答案可信、能直接出文件 |
| **业务专家 / 部门管理员** | 部门骨干、HR、财务、法务 | 流程标准化 | 能配置本部门技能、模板、知识库 |
| **IT 平台管理员** | 信息中心 | 可控、可查、不背锅 | 权限、审计、成本、稳定性 |
| **安全 / 合规** | 风控、内审 | 数据不越界 | 数据边界、留痕、可追责 |
| **开发者** | 内部研发 | 可扩展 | 开放 API、插件/连接器 SDK |

> 设计含义：**同一个人在不同场景下是不同角色**。权限模型必须支持「员工 + 某部门管理员」的叠加，而不是一人一角色。

## 4. 设计原则（产品侧）

1. **默认给出「可交付物」**：用户要的是报告、邮件草稿、表格，不是一个聊天回答。
2. **可信优先于聪明**：所有知识类回答必须带来源（哪个文件、第几页）；无来源时必须明说「我不确定」。
3. **人机协同，不是全自动**：从「AI 做 → 人确认」起步，逐步放开到「AI 做 → 事后审计」。
4. **能力分级而非功能阉割**：不同角色看到的是不同能力集合，而不是同一个产品被砍功能。
5. **零学习成本**：员工第一次使用不需要培训；管理员第一次配置不超过 10 分钟。
6. **可退出**：任何由 Agent 产生的变更都能看到 diff、能回滚。

## 5. 范围边界（第一版明确不做）

| 不做 | 原因 | 何时再议 |
|---|---|---|
| 自主对外发信（无人工确认） | 风险远大于收益 | P3，且需白名单 |
| 跨部门数据自由检索 | 权限穿透风险 | 待权限模型成熟 |
| 替代正式审批流 | 合规要求签批留痕 | 不做，只做「辅助填单」 |
| 移动端完整功能对齐 | 企微内置浏览器能力受限 | 移动端只做轻交互 |
| 自研基础大模型 | 成本极高 | 只做私有化部署与微调 |
| 面向外部客户 | 内部系统定位不同 | 单独立项 |

## 6. 成功指标

| 维度 | 指标 | 目标（试点期） |
|---|---|---|
| 采用度 | 周活跃用户 / 覆盖人数 | ≥ 60% |
| 深度 | 人均周会话数 / 人均周生成文件数 | ≥ 5 / ≥ 2 |
| 价值 | 自评每周节省时间 | ≥ 3 小时 |
| 质量 | 知识问答准确率（带正确引用） | ≥ 85% |
| 质量 | 幻觉率（无依据却给出肯定答案） | ≤ 3% |
| 安全 | 越权访问事件 | 0 |
| 安全 | 敏感信息外发事件 | 0 |
| 成本 | 单活跃用户月成本 | 设定硬上限并监控 |
| 稳定 | 核心接口可用性 | ≥ 99.5% |

## 7. 关键假设与待验证点

- **假设 1**：员工最大的痛点是「信息分散 + 重复写作」，而非「不会用 AI」。→ 需访谈验证。
- **假设 2**：企微是移动端唯一现实入口。→ 需确认企微自建应用审批链路。
- **假设 3**：公司数据出内网受限。→ 决定 D1/D2/D3 决策，尽早确认。
- **风险 1**：如果首批场景选得太泛，会得到「什么都能聊、什么都做不好」的评价。
- **风险 2**：如果桌面端先做「本机文件全盘可读」，安全评审会直接卡死。必须一开始就是白名单授权目录。
