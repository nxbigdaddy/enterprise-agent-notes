# 06 · 桌面端本地能力

> 版本：v0.1（草稿） · 对应需求：「桌面端 对本机文件的管理，对本地各个系统进行链接」

## 1. 定位

桌面端有两个身份：

1. **更强的 Web 端**——大屏、常驻、系统通知、全局快捷键。
2. **本机能力代理**——唯一能碰本机文件和本地系统的组件，也是**最大的安全风险面**。

因此桌面端的一切设计都要围绕一个问句：**「这个能力，用户知情吗？可撤销吗？可审计吗？」**

## 2. 架构

```
┌───────────────── 桌面端应用（Electron/Tauri） ─────────────────┐
│  渲染进程（= Web 前端）                                        │
│      ↕ IPC（受控白名单通道，不做任意方法透传）                    │
│  主进程 / 本地能力代理                                         │
│   ├─ 文件服务（白名单目录 · 读写 · 索引 · 批量操作）              │
│   ├─ 本地工具注册表（声明本机能提供哪些 Tool）                    │
│   ├─ 本地 MCP / 插件宿主（连接本地系统）                         │
│   ├─ 系统集成（剪贴板、截图、拖拽、托盘、通知、快捷键）             │
│   └─ 本地策略引擎（白名单、危险操作拦截、二次确认）                │
└───────────────┬───────────────────────────────────────────────┘
                │ WSS 长连接（仅出站）
        ┌───────▼────────┐
        │  云端 Agent     │
        └────────────────┘
```

**关键点**：桌面端**只主动外连**，不开监听端口；服务端不能反向连入用户机器。

## 3. 本机文件管理

### 3.1 授权目录（白名单）—— 最核心的设计

- 用户**显式**添加授权目录（如 `D:\工作`），默认**不授权任何目录**。
- 系统敏感目录**永久禁止**授权（Windows 目录、浏览器配置、凭据目录、其他用户目录、`AppData` 等）。
- 支持三种权限级别：`只读` / `读写` / `读写+删除`，逐目录配置。
- 可随时撤销授权；撤销后索引立即失效。
- 授权状态在 UI 上**始终可见**（状态栏常显「已授权 3 个目录」）。

### 3.2 文件能力

| 能力 | 说明 | 默认权限 |
|---|---|---|
| 列表 / 搜索 | 按名称、内容、时间、类型检索授权目录 | 只读 |
| 内容解析 | docx/xlsx/pptx/pdf/txt/md 的文本与结构提取 | 只读 |
| 读取内容 | 交给 Agent 分析（需明示上传） | 只读 |
| 新建 / 写入 | 生成文档到指定目录 | 读写 |
| 批量重命名 / 归档 | 按规则整理文件 | 读写 |
| 格式转换 | docx↔pdf、xlsx↔csv 等 | 读写 |
| 删除 | **永不自动执行**，必须逐次确认 | 删除 |
| 移动 / 复制 | 批量操作需预览影响列表 | 读写 |

### 3.3 本地索引（可选，P2）

- 本地建立轻量索引（文件名 + 可选内容索引），**索引不出本机**。
- 查询时只把**命中的片段**上传，路径信息可脱敏（只传文件名或仅传内容）。
- 让用户可以选择「不建立内容索引」，只用文件名检索。

### 3.4 文件操作的安全约束

1. **所有写/删操作先给 diff 或影响预览**。
2. **删除进回收站**，不做物理删除；提供撤销入口。
3. **操作日志本地留一份**（用户可查「Agent 对我电脑做了什么」），同时上报审计。
4. **不在用户不知情时上传任何文件内容**；上传前展示清单。
5. **批量操作有数量上限与频率限制**（如单次 ≤ 200 个文件），超出需二次确认。

## 4. 连接本地系统

「对本地各个系统进行链接」是桌面端最有价值也最难的部分。建议按**四类通道**分层实现：

### 4.1 通道 A：本地 MCP / 插件宿主（推荐主路径）

把「本地系统能力」抽象为**本地工具**，用统一的协议（MCP 或自研等价物）注册到 Agent 运行时。

```
本地插件（plugin.json 声明）
  ├─ 工具声明：名称、参数 schema、风险等级、所需权限
  ├─ 传输：stdio / 本地 HTTP / 本地 socket
  └─ 生命周期：随应用启动、崩溃自恢复、可禁用
```

优点：新增一个本地系统只需要写一个插件，不动主程序。

**适用**：有本地服务或能写适配器的系统。

### 4.2 通道 B：本地服务的 HTTP / 数据库直连

| 对象 | 方式 | 注意 |
|---|---|---|
| 本地部署的 Web 系统 | 调用其 HTTP API | 凭据存本地密钥库，不上传 |
| 本地数据库 | 只读连接（优先视图/只读账号） | 严禁写生产库；查询超时与行数限制 |
| 本地文件型数据 | 直接解析 | 如 Excel、Access、CSV |
| 本地服务发现 | 扫描常见端口/配置文件 | **需用户确认**，不做静默扫描 |

### 4.3 通道 C：RPA / 浏览器自动化（兜底）

对于**没有 API 的老系统（C/S 客户端、只能手工点的网页系统）**：

- 浏览器自动化（Playwright 类）：登录后自动填表、取数、下载报表。
- 桌面 UI 自动化（Windows UI Automation / 无障碍接口）：操作传统客户端。

约束（必须写进设计）：

- 只允许在**用户已登录的会话**中操作，不代管密码（除非用户显式存入凭据库）。
- 操作过程**屏幕可见**，不做无头静默运行（可提供"演示模式"）。
- **敏感动作必须停下来等确认**（提交、审核、付款、删除）。
- 录制→回放的脚本要能人工编辑，且版本化。
- 老系统改版会失效，必须有失败告警，不能静默失败。

### 4.4 通道 D：CLI / 脚本执行

- 允许在**受控环境**中执行本地命令（如 git、内部工具）。
- 命令白名单 + 参数校验，禁止管道拼接任意 shell。
- 有超时、有输出上限、有工作目录限制。

### 4.5 本地系统连接的权限模型

每个本地工具声明：

```json
{
  "name": "local.erp.exportOrder",
  "riskLevel": "medium",
  "requiredCapability": "local.tool.erp",
  "localScope": "authorized_dir_only",
  "requiresConfirm": false,
  "auditLevel": "full"
}
```

运行时校验**双端**：服务端查用户能力 + 本地代理查本地策略。任一不通过即拒绝。

## 5. 系统集成能力

| 能力 | 说明 |
|---|---|
| 全局快捷键 | 唤起助手（默认 `Alt+Space`），选中文本直接问 |
| 悬浮窗 / 划词 | 选中文字 → 翻译/润色/解释/生成回复 |
| 拖拽 | 把文件拖进窗口即加入上下文 |
| 剪贴板 | 默认**不读取**；用户显式「读取剪贴板」才读 |
| 截图 | 截图 → OCR → 提问 |
| 托盘常驻 | 关闭主窗口后继续执行长任务，托盘显示任务状态 |
| 系统通知 | 任务完成、需确认时的原生通知 |
| 开机自启 | 可选，默认关闭 |
| 文件关联 | 右键菜单「用 AI 助手打开」（可选） |

## 6. 安全设计清单（评审必查）

| # | 要求 |
|---|---|
| 1 | 默认零授权，所有目录需用户显式添加 |
| 2 | 系统敏感目录黑名单，不可解锁 |
| 3 | 不上传未确认的内容；上传有明细提示 |
| 4 | 删除操作必须逐次确认 + 进回收站 + 可撤销 |
| 5 | 本机操作日志用户可见可导出 |
| 6 | 凭据存系统密钥库（Keychain/DPAPI），不落明文 |
| 7 | 只出站、不开监听端口 |
| 8 | 插件需签名或来源可信，禁用未签名插件（可配置） |
| 9 | 更新包签名校验，防中间人替换 |
| 10 | 远程可吊销设备授权；离职后立即失效 |
| 11 | 卸载时清理本地缓存、索引与凭据 |
| 12 | 本地策略引擎独立于服务端，服务端被攻陷也不能越权操作本机 |
| 13 | RPA 敏感动作强制人工确认 |
| 14 | 剪贴板/屏幕内容默认不采集 |
| 15 | 支持"演示模式"：显示 Agent 的每一步本机动作 |

## 7. 技术选型

| 方案 | 优点 | 缺点 | 建议 |
|---|---|---|---|
| **Electron** | 生态成熟、Node 原生能力强、三端共用前端代码 | 包大（100MB+）、内存占用高 | **推荐首选**，桌面能力需求多，开发效率优先 |
| **Tauri** | 包小、内存低、Rust 安全 | 本地能力需写 Rust、生态较新 | 若对包体/性能敏感可选 |
| 纯 Web + 本地插件 | 无需安装 | 无法管理本机文件 | 不满足需求 |

> **重要**：Electron 在**调用本机 C/C++/.NET 生态**（COM / Office 自动化 / Windows UI Automation / 厂商硬件 DLL / ODBC）上存在明确短板，必须用 **Python sidecar** 补齐。完整能力对照与架构见 [11-桌面端Electron能力边界.md](./11-桌面端Electron能力边界.md)。
>
> 落点：本地插件协议做成 **MCP 兼容 + stdio 传输**，则 Python sidecar 天然就是一个本地 MCP Server，无需另造协议。

5. 桌面端是否需要支持国产信创操作系统（麒麟/统信）？
