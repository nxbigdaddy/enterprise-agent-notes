# 07 · 邮件管理

> 版本：v0.1（草稿） · 对应需求：「邮件管理功能」

## 1. 功能定位

邮件是国内办公最高频、也最耗时的信息入口。Agent 在邮件上的价值排序：

1. **分类与降噪**——把 100 封变成 10 封值得看的
2. **摘要与提取**——长邮件一句话说清，自动抽待办与截止时间
3. **拟稿**——基于上下文写出可直接发的回复（但默认只存草稿）
4. **跟进**——谁没回、什么事到期，主动提醒
5. **归档与检索**——附件自动归类，跨邮件检索

## 2. 协议与系统接入

| 邮件系统 | 接入方式 | 说明 |
|---|---|---|
| Exchange / M365 | Microsoft Graph API（首选）/ EWS | Graph 支持增量同步、订阅推送，能力最全 |
| 腾讯企业邮 / 腾讯企邮 | IMAP + SMTP | 国内常见 |
| 阿里/网易企业邮 | IMAP + SMTP + 专用 API | 按可用文档选 |
| 自建（Postfix/Zimbra 等） | IMAP + SMTP | 通用兜底 |
| Gmail | Gmail API | 如需 |

**统一抽象层**：不要在多处直接写各协议细节，抽象成 `MailProvider` 接口：

```
listFolders() / listMessages(query, pageToken)
getMessage(id) / getAttachment(id)
send(draft) / saveDraft(draft) / move(id, folder) / setFlags(id, flags)
subscribe(callback)   // 支持推送的走推送，不支持的走轮询
```

同步策略：

- **增量同步**（`historyId` / `UIDVALIDITY+UID` / `since`），不做全量拉取。
- **推送优先**（Graph 订阅、IMAP IDLE），轮询兜底。
- **去重**：以 `Message-ID` 为主键。
- **会话聚合**：按 `References/In-Reply-To` 归并成 thread。
- 首次同步限最近 N 天（如 90 天），历史邮件按需拉取，避免开账号即拖垮系统。

## 3. 功能清单

### 3.1 收件（P0）

| 功能 | 说明 |
|---|---|
| 自动分类 | 规则优先（发件人/域名/主题关键词/是否含附件），模型兜底 |
| 优先级排序 | 结合发件人重要性（上级/客户）、是否 @ 我、是否需回复、截止时间 |
| 一键摘要 | 单封摘要 / 今日邮件汇总 / 某 thread 全流程摘要 |
| 待办抽取 | 从邮件中抽出「谁要什么、什么时候要」→ 待办中心 |
| 附件处理 | 自动按规则归档到指定目录 / 云盘，并建立索引 |
| 垃圾与营销过滤 | 辅助过滤，不做唯一判断依据 |

### 3.2 发件与回复（P0，高风险）

| 功能 | 说明 | 安全策略 |
|---|---|---|
| 拟回复草稿 | 基于 thread 上下文生成回复 | **只存草稿，不自动发** |
| 语气与模板 | 正式/简洁/英文，套用公司模板 | — |
| 附件建议 | 根据对话内容提示该带哪个文件 | — |
| 收件人建议 | 基于 thread 与通讯录 | 需用户确认 |
| **直接发送** | 增强用户可用 | 白名单域 + 人工确认 + 可撤回窗口 |
| 定时发送 | 到点发送 | 发送前再确认一次 |
| 合并发送 | 群发个性化（P2） | 频率限制，防误发 |

**发送安全策略（必须实现）**

1. 默认**永远只生成草稿**。
2. 开启直接发送需满足：用户是增强用户 + 收件人在允许域内 + 单次收件人 ≤ N 人。
3. 发送前必须展示：收件人、抄送、主题、正文全文、附件清单。
4. 发送后给一个**撤回窗口**（如同系统支持的「延迟发送 30 秒」）。
5. 附件外发前做**敏感信息检测**（密级、关键词、客户名单）。
6. 全量留痕：谁、何时、发给了谁、什么内容、谁确认的。

### 3.3 跟进与提醒（P1）

- 「已发出但 X 天无回复」提醒
- 「对方承诺了 deadline」到期提醒
- 「我答应别人的事」自动进待办
- 智能催办：一键生成催办邮件草稿
- 跟进看板：按客户/项目聚合往来邮件

### 3.4 检索与归档（P1）

- 自然语言检索：「上个月张总发的关于预算的邮件」
- 跨邮件、附件、知识库的**统一搜索**
- 附件全文索引（含 PDF/Office 内容）
- 自动归档规则：项目 → 文件夹 / 标签

### 3.5 与其他模块联动（P1/P2）

| 联动 | 说明 |
|---|---|
| 日历 | 邮件中的会议邀请 → 自动加日程 |
| 待办中心 | 邮件待办与任务统一视图 |
| CRM | 客户来信 → 写回 CRM 记录（P2） |
| 知识库 | 有价值邮件转为知识条目（需权限控制） |
| 文档服务 | 附件自动解析、汇总成表 |
| 工作流 | 「收到带附件的邮件」作为触发器 |

## 4. 权限与隐私

| 项 | 策略 |
|---|---|
| 访问范围 | **仅本人邮箱**；共享邮箱/部门邮箱需显式授权 |
| 管理员可见性 | 管理员**默认不可读员工邮件内容**；仅能看到用量与安全事件元数据 |
| 例外通道 | 合规调查需走正式审批 + 全程留痕 |
| 邮件进知识库 | 默认**不进**共享知识库；仅本人可检索自己的邮件 |
| 附件外发 | 密级检测 + 审批 |
| 凭据 | OAuth token / IMAP 密码存密钥库，加密存储，不明文落库 |

## 6. 实现要点与坑

1. **首次同步是性能陷阱**——必须限制时间窗口，异步建索引，别阻塞用户登录。
2. **不要解析 HTML 就用**——要清洗（去追踪像素、去外链重写），否则正文一团糟。
3. **附件要防病毒**——至少接一个扫描服务，或强制下载到隔离区。
4. **模型摘要要缓存**——同一封邮件不要重复调用模型（成本杀手）。
5. **时区与编码**——中文邮件编码（GB2312/GBK）与乱码是经典问题。
6. **回复全部 vs 回复**——这两个操作很容易搞错，UI 必须区分明显。
7. **撤回窗口**依赖邮件系统能力，别承诺做不到的事。
8. **发信限流**——防止 Agent 循环发信，必须有人/天/收件人三级上限。
