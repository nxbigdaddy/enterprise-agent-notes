# 09 · 路线图与里程碑

> 版本：v0.1（草稿）
> 说明：周期为**相对估算**，需按实际人力调整。默认按「3~5 人小团队 + 1 名产品」估算。

---

## 1. 总体思路

```
阶段 0  立项与验证      → 确认边界，避免返工
阶段 1  平台底座        → AI 网关 + 用户权限 + 审计 + 通知
阶段 2  标杆场景        → 邮件 + 知识库 + 文档（三个闭环）
阶段 3  多端与自动化    → 桌面端本地能力 + 工作流 + 连接器
阶段 4  平台化          → 技能市场 + 开放能力 + 规模化运营
```

**核心节奏**：先把「能管住」建好（阶段 1），再放「能干活」的能力（阶段 2）。顺序反了，后面每加一个功能都要补一遍安全与权限。

---

## 2. 阶段 0 · 立项与验证（2~3 周）

| 交付物 | 内容 |
|---|---|
| 需求确认 | 本文档集评审通过，待决策清单 D1~D10 全部拍板 |
| 场景定标 | 选定 2 个试点部门 + 3 个标杆场景 |
| 技术验证（PoC） | ① 一个模型跑通（外部 API + 自建各一）② 一份 PDF 能检索并给出引用 ③ 桌面端能读一个授权目录 |
| 环境准备 | 企微自建应用创建并审批通过、测试环境、GPU/API 额度 |
| 基线指标 | 记录当前人工耗时，作为后续 ROI 对比基准 |

**通过标准**：PoC 三项全部跑通，且数据出境问题有明确结论。

**风险**：企微应用审批、数据出境结论这两项常是长尾，**必须最先启动**。

---

## 3. 阶段 1 · 平台底座（6~8 周）

| 模块 | 交付内容 |
|---|---|
| 接入层 | 网关 + BFF + 鉴权 + 限流 + 审计埋点 |
| AI 能力网关 | 模型注册、OpenAI 兼容代理、路由、配额、成本记录、密钥托管 |
| 用户与权限 | 企微组织同步、SSO（Web/桌面扫码、移动免登）、RBAC、能力开关、数据范围 |
| 审计中心 | 统一日志格式、写入、检索、任务回放 |
| 通知中心 | 站内信 + 企微推送 + 桌面通知（统一接口） |
| 管理后台 v1 | 用户、角色、模型、配额、审计四大模块 |
| 可观测性 | Trace、指标大盘、告警 |

**验收标准**

- 三端能登录并拿到正确的能力集合；
- 一次问答在不同密级下走到正确的模型；
- 能按人查出成本与调用明细；
- 能回放一次完整任务链；
- 模型不可用时系统降级而不是整体不可用。

---

## 4. 阶段 2 · 标杆场景（8~10 周）

| 场景 | 交付内容 | 验收 |
|---|---|---|
| **知识问答** | 制度/流程/产品文档入库、权限继承、混合检索、引用溯源 | 试点部门问答准确率 ≥ 85%，引用正确率 ≥ 90% |
| **邮件助手** | 增量同步、分类、摘要、待办抽取、回复草稿 | 试点用户邮件处理时间下降 ≥ 30% |
| **文档生成** | 从材料生成周报/汇报，导出 Word/PPT | 一份周报从 60 分钟降到 10 分钟内 |

同期补齐：待办中心、个人工作台首页、模板中心（基础）、反馈闭环。

**关键动作**

- 每个场景建立**评测用例集**，改模型/改 Prompt 必跑回归。
- 每周收集 badcase，回流到评测集。
- 试点用户一对一访谈，重点问「哪次它答错了 / 哪次你不敢用」。

---

## 5. 阶段 3 · 多端与自动化（10~12 周）

| 模块 | 交付内容 |
|---|---|
| 桌面端 v1 | Electron 应用：授权目录管理、文件读取、文档生成落盘、系统通知、全局快捷键、托盘常驻 |
| 移动端 v1 | 企微自建应用 H5：问答、摘要、待办、确认类交互、企微推送 |
| 三端互通 | 会话跨端续接、文件跨端流转、统一任务状态 |
| 工作流引擎 | 定时任务、事件触发、条件分支、人工确认节点 |
| 连接器 v1 | 优先接 2~3 个高频系统（OA / 网盘 / 日历） |
| 本地插件体系 | 本地工具注册协议 + 本地策略引擎 |
| 管理后台 v2 | 知识库、连接器、技能、设备管理 |

**验收标准**

- 桌面端：默认零授权的目录白名单机制通过安全评审；所有本机操作可审计、可撤销。
- 移动端：企微内完成一次「确认发送邮件」全流程。
- 跨端：桌面端发起的会话，手机上能无缝继续。
- 工作流：至少 1 条无人值守流程稳定运行 2 周无人工干预。

---

## 6. 阶段 4 · 平台化与规模化（持续）

- 技能市场：部门自助创建并共享技能
- 开放平台：内部系统可调用 Agent 能力（带配额与审计）
- 多 Agent 协作：复杂流程拆分执行
- 数据问答（Text2SQL）与报表自动化
- 评测平台完善、A/B 实验
- 成本优化：智能路由（简单问题走小模型）
- 运营：使用分析、推广、培训、案例集

## 7. 里程碑总览

| 里程碑 | 时间（相对） | 标志 |
|---|---|---|
| M0 需求冻结 | T+3 周 | 待决策清单全部关闭 |
| M1 底座可用 | T+10 周 | 三端能登录，能力分级生效，能审计 |
| M2 场景闭环 | T+20 周 | 3 个标杆场景上线试点部门 |
| M3 多端自动化 | T+32 周 | 桌面+移动+工作流全部可用 |
| M4 平台化 | 持续 | 部门可自助扩展 |

## 8. 团队建议

| 角色 | 人数 | 职责 |
|---|---|---|
| 产品经理 | 1 | 场景、需求、验收、试点运营 |
| 后端（平台） | 1~2 | 网关、权限、审计、配额 |
| 后端（应用） | 1~2 | Agent 运行时、RAG、邮件、工作流 |
| 前端 | 1~2 | Web + 桌面 + 移动 |
| 算法/数据 | 0.5~1 | Prompt、评测、检索调优、模型部署 |
| 测试 | 0.5~1 | 回归、安全测试、多端兼容 |
| 运维 | 0.5 | 部署、监控、GPU 集群 |

**最小可行团队**：3 人（1 全栈 + 1 后端 + 1 产品），周期相应拉长 1.5 倍。

## 9. 风险登记册

| # | 风险 | 影响 | 应对 |
|---|---|---|---|
| R1 | 数据出境结论未定 | 架构返工 | 阶段 0 先做，默认按"不许出网"设计 |
| R2 | 企微应用审批慢 | 移动端延期 | 阶段 0 提交申请，移动端不阻塞主线 |
| R3 | 桌面端安全评审不通过 | 核心卖点缺失 | 从第一行代码就是白名单 + 可审计，提前拉安全团队评审 |
| R4 | RAG 越权事故 | 信任崩塌 | 先过滤后召回，权限实时判定，上线前做越权测试用例 |
| R5 | 成本失控 | 项目被砍 | 网关硬上限 + 每周成本例会 + 智能路由 |
| R6 | 场景选得太泛 | 「什么都能，什么都做不好」 | 3 个标杆场景做到 90 分，其余先不做 |
| R7 | 试点用户不用 | 无法推广 | 选真实痛点部门，配"驻场支持"，每周收集反馈 |
| R8 | 知识库内容荒废 | 回答质量差 | 明确知识责任人 + 过期机制 + 每月治理 |
| R9 | 老系统无 API | 连接器做不完 | 先用 RPA 兜底，同时推动系统方开 API |
| R10 | 模型供应商变更/涨价 | 成本与稳定性 | 网关抽象 + 至少两家备选 + 自建兜底 |
