# 02 · 总体架构与部署

> 版本：v0.1（草稿）

## 1. 分层架构

```
┌──────────────────────────── 客户端层 ────────────────────────────┐
│   Web 端（浏览器）   │   桌面端（Win/macOS）   │  移动端（企微 H5）  │
│                      │  含本地能力代理进程     │                    │
└───────┬──────────────────────┬───────────────────────┬───────────┘
        │ HTTPS / WSS          │ HTTPS / WSS 长连接     │ 企微 JSSDK + HTTPS
┌───────▼──────────────────────▼───────────────────────▼───────────┐
│                     统一接入层（API Gateway / BFF）                │
│   鉴权 · 会话管理 · 限流 · 路由 · 协议转换 · 审计埋点 · 多端适配      │
└───────┬──────────────────────────────────────────────────────────┘
        │
┌───────▼──────────────────────────────────────────────────────────┐
│                        应用与能力服务层                            │
│  Agent 运行时  │ 知识库/RAG │ 文档处理 │ 邮件服务 │ 日程会议 │ 工作流引擎 │
│  连接器中心    │ 通知中心   │ 统一搜索 │ 模板中心 │ 报表数据 │ 技能市场   │
└───────┬──────────────────────────────────────────────────────────┘
        │
┌───────▼──────────────────────────────────────────────────────────┐
│                            平台底座                                │
│  AI 能力网关 │ 用户/组织/权限 │ 审计中心 │ 配额与成本 │ 配置中心 │ 可观测性 │
└───────┬──────────────────────────────────────────────────────────┘
        │
┌───────▼──────────────────────────────────────────────────────────┐
│  基础设施：推理集群(GPU) · 向量库 · 对象存储 · 关系库 · 缓存 · MQ · 沙箱 │
└──────────────────────────────────────────────────────────────────┘
```

**分层职责要点**

| 层 | 职责 | 不该做的事 |
|---|---|---|
| 客户端层 | 交互、渲染、本机能力（仅桌面端） | 不做权限判断（可做 UI 隐藏，但服务端必须再校验） |
| 接入层 | 认证、路由、限流、审计埋点 | 不写业务逻辑 |
| 服务层 | 业务能力实现、Agent 编排 | 不直连模型厂商（统一走 AI 网关） |
| 底座层 | 横切治理能力 | 不感知具体业务场景 |
| 基础设施 | 存储与算力 | —— |

## 3. 三端数据流（关键路径）

### 3.1 一次普通问答

```
客户端 → 接入层(鉴权) → Agent 运行时
                          ├─ 权限服务：算出「本次可见的数据范围」
                          ├─ 知识库：按范围检索 → 重排 → 拼装上下文(带引用)
                          ├─ AI 网关：路由到模型 → 记录用量
                          └─ 回流：答案 + 引用 + 用量 → 客户端
```

### 3.2 桌面端本机文件操作

```
桌面端 UI → 本地能力代理(校验目录白名单)
              ├─ 若为只读操作：直接本地执行，结果上报审计
              └─ 若涉及模型/云端：把「必要的最小内容」上传，本机路径只传元数据
         → 服务端 Agent 决策 → 下发工具调用指令 → 本地代理执行 → 结果回报
```

**原则**：本机文件**默认不上云**；只有用户显式提交的那一份内容才上传，并在 UI 上明示。

### 3.3 邮件自动分类与汇总

```
邮件服务(增量同步) → 规则粗分类 → 模型摘要/打标 → 存元数据
   → 定时任务聚合 → 通知中心 → 三端可见（Web/桌面/企微推送）
```

## 4. 部署形态

| 形态 | 说明 | 适用 | 代价 |
|---|---|---|---|
| **A. 全私有化** | 全部组件内网部署，自建推理集群 | 数据严禁出网 | 成本最高，GPU 与运维投入大 |
| **B. 混合（推荐起点）** | 平台组件私有化；**敏感数据走自建模型，非敏感走外部 API** | 大多数公司 | 需要清楚的数据分级与路由策略 |
| **C. 公有云为主** | 全部托管 | 数据敏感度低、求快 | 合规风险 |

**混合模式的关键**：在 AI 网关上做**数据分级路由**——请求带数据密级标签，网关按标签决定走内网模型还是外部 API；不可判定的默认走内网。

### 4.1 推荐初始拓扑（形态 B）

```
内网区
├── 接入网关 + BFF（2 节点）
├── 应用服务集群（容器化，K8s 或 Compose）
├── 推理节点：vLLM/Ollama（1~2 台 GPU 服务器，承载敏感请求 + embedding/rerank）
├── 向量库 + 关系库 + 对象存储（主备）
└── 出网代理（白名单，仅 AI 网关可出网）

DMZ / 出网
└── 外部模型 API（OpenAI/Claude/国产大模型），仅承载 ✅非敏感 请求
```

## 5. 非功能要求

| 类别 | 要求 |
|---|---|
| **可用性** | 核心问答链路 ≥ 99.5%；模型不可用时降级为「无 AI 的常规功能」而非整体不可用 |
| **性能** | 首字延迟 ≤ 2s；普通问答端到端 ≤ 10s；长任务异步 + 进度可见 |
| **限流** | 按用户 / 部门 / 应用三级令牌桶；超限排队而非直接失败 |
| **熔断降级** | 外部 API 故障 → 切自建模型 → 切轻量模型 → 明确告知用户 |
| **成本** | 每次调用记录 token/费用；支持硬上限，超额阻断并告警 |
| **数据** | 全量加密（传输 TLS、存储 AES）；密钥托管在 KMS/Vault，不入代码库 |
| **审计** | 关键操作（发信、改文件、导出、权限变更）100% 留痕，保留期按合规要求 |
| **扩展** | 新增模型/工具/连接器不改核心代码，走注册表 |
| **容灾** | 数据库主备 + 定期备份演练；对象存储多副本 |
| **可观测** | 每次 Agent 任务有 trace_id，可回放完整决策链 |

## 6. 技术选型建议

> **约束：不使用任何 Java / JVM 相关技术。** 完整选型与替代映射见 [10-技术栈选型.md](./10-技术栈选型.md)。

| 领域 | 选择 | 说明 |
|---|---|---|
| 后端 | **Python 3.12 + FastAPI**（单栈） | 业务 + AI 同一应用，按模块划分包边界 |
| 工作流/长任务 | **Temporal**（Go 服务端 + Python SDK） | 断点续跑、重试、等待人工确认 |
| AI 网关 | **LiteLLM**（Proxy 模式） | 统一模型协议、路由、预算、日志 |
| 前端 | React 18 + TypeScript + Vite | 三端共用组件库与类型 |
| 桌面端 | **Electron**（首选） / Tauri（备选） | 本地能力重，Node 生态现成 |
| 移动端 | 企微内置浏览器 H5（React） | 不做原生 App |
| Agent 编排 | 自研轻量编排（LlamaIndex 仅用于实验） | 权限与引用溯源必须自己掌控 |
| 向量库 | pgvector（起步）→ Qdrant / Milvus | pgvector 起步最省事 |
| 文档解析 | Docling + python-docx/openpyxl/python-pptx/PyMuPDF | 不用 Tika/POI |
| 存储与中间件 | PostgreSQL 16 + Redis/Valkey + MinIO + RabbitMQ | 起步三件即可 |
| 日志检索 | Loki → Quickwit / OpenObserve | **不用 ES/OpenSearch** |
| LLM 可观测 | Langfuse（自托管） | prompt/token/成本/工具链 |
| 推理 | vLLM（生产） / Ollama（轻量） | OpenAI 兼容 |
| 沙箱 | 容器隔离（gVisor 可选） | 代码执行必须隔离 |

## 7. 架构上的三条红线

1. **任何服务不得绕过 AI 网关直连模型**——否则配额、审计、脱敏全部失效。
2. **任何检索不得绕过权限过滤**——RAG 的越权是内部 Agent 最常见的事故。
3. **任何本机操作不得绕过目录白名单与用户可见性**——桌面端是最大的信任边界。
