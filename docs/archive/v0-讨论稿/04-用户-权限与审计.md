# 04 · 用户、权限与审计

> 版本：v0.1（草稿） · 对应需求：「统一的用户管理」「基础功能 + 不同功能的用户不同的功能」

## 1. 身份与组织

### 1.1 账号来源（单一事实源）

**企业微信通讯录为主数据源**（因为移动端以企微为入口，且企微已是公司组织事实源），AD/LDAP 为备选或补充。

| 事项 | 方案 |
|---|---|
| 组织架构同步 | 定时（每小时）+ 事件回调，同步部门树、人员、岗位、上级 |
| 登录方式 | 企微扫码登录（Web/桌面）、企微 H5 免登（移动端） |
| 桌面端授权 | 首次扫码登录，之后本地保存 refresh token（可被管理员远程吊销） |
| 账号状态 | 离职/停用 → 同步后立即冻结，会话与 token 全部失效 |
| 一人多角色 | 支持「员工 + 部门管理员 + 某项目成员」叠加 |

### 1.2 用户档案

除组织信息外，还需要业务字段：

- 常驻部门 / 兼职部门
- 数据密级上限（决定他最多能看到什么级别的数据）
- 可用能力集（基础 / 增强 / 管理员）
- 成本额度
- 设备绑定情况（桌面端可绑定的设备数）

## 2. 权限模型

采用 **RBAC + ABAC 混合**：

```
权限判定(user, action, resource) =
    RBAC 角色是否包含 action
    AND ABAC 数据条件成立(部门/密级/项目/本人)
    AND 能力开关已开通
```

### 2.1 三层权限

| 层 | 管什么 | 例子 |
|---|---|---|
| **功能权限（能力）** | 能不能用这个功能 | 邮件发送、本机文件写入、知识库管理、连接器配置 |
| **数据权限** | 能看哪些数据 | 本部门文档、本人邮件、公开知识库；密级 ≤ 内部 |
| **操作权限** | 能做多重的操作 | 只读 / 可写 / 可删 / 可对外发送 |

### 2.2 角色设计（建议）

| 角色 | 能力 |
|---|---|
| **员工（默认）** | 问答、知识检索、文档生成、邮件读写（草稿）、本机只读 |
| **增强用户** | + 邮件直接发送（白名单内）、本机文件写入（授权目录）、批量任务、数据问答 |
| **部门管理员** | + 本部门知识库、模板、技能、成员额度管理 |
| **平台管理员** | 全平台配置、模型、配额、连接器 |
| **安全审计员** | 只读访问审计日志与报表，不能改配置（职责分离） |
| **开发者** | 连接器/技能开发、调试沙箱 |

**职责分离原则**：能改配置的人不能清日志，能看审计的人不能改权限。

### 2.3 能力分级的具体落地

每个**工具（Tool）**在注册时必须声明：

```json
{
  "name": "mail.send",
  "displayName": "发送邮件",
  "riskLevel": "high",
  "requiredCapability": "mail.send",
  "requiresConfirm": true,
  "auditLevel": "full",
  "dataScope": "user_own"
}
```

Agent 运行时在调用前做一次**服务端强校验**（不能只靠前端隐藏按钮）；无权限时给出明确提示，并引导「申请开通」流程。

### 2.4 数据权限与 RAG 的权限继承（重点）

**这是内部 Agent 最容易出事故的地方。**

要求：

1. 知识库文档入库时，**继承源系统的权限标签**（部门、密级、项目、可见人列表）。
2. 检索时**先过滤后检索**（pre-filter），而不是检索完再过滤——否则向量库会被越权内容污染结果。
3. Embedding 时保留权限字段，作为向量库的标量过滤条件。
4. 邮件/本地文件这类「个人数据」默认只对本人可见，不进入共享知识库。
5. 用户权限变更后，**检索侧即时生效**（权限判定实时查，不缓存在向量里）。

> 反模式：把所有文档灌进一个知识库，然后指望 Prompt 里写「请不要透露无权限内容」。这等于没有权限。

## 3. 敏感操作与人工确认

| 操作 | 默认策略 | 可放开条件 |
|---|---|---|
| 读取邮件 | 允许（仅本人邮箱） | — |
| 撰写邮件草稿 | 允许 | — |
| **发送邮件** | **必须确认** | 白名单域内 + 增强用户 → 可设为「3 秒内可撤回」 |
| 读取本机文件 | 仅授权目录 | — |
| 修改/删除本机文件 | **必须确认 + 显示 diff** | 增强用户可对指定目录免确认 |
| 对外提交表单/审批 | **必须确认** | 不放开 |
| 导出数据 | 需审批 | 密级 ≤ 内部 |
| 权限配置变更 | 需二次验证 | — |

确认交互要求：

- 说清 **要做什么 / 对什么做 / 影响范围**；
- 尽量给出 **预览或 diff**；
- 提供 **撤销** 入口（哪怕只有 5 分钟窗口）。

## 4. 审计

### 4.1 记录什么

| 类别 | 事件 |
|---|---|
| 认证 | 登录、登出、失败尝试、token 刷新、设备绑定 |
| 权限 | 角色变更、能力开通、数据范围调整、审批 |
| AI 调用 | 每次模型调用的 trace（模型、耗时、成本、密级路由结果） |
| 工具调用 | 工具名、参数摘要、结果状态、是否人工确认 |
| 数据访问 | 读了哪些文档/邮件/表，命中了什么权限过滤 |
| 敏感操作 | 发信、改文件、删除、导出、外部提交 |
| 管理操作 | 配置变更、模型注册、配额调整、Prompt 发布 |
| 安全事件 | 脱敏拦截、注入检测命中、越权尝试 |

### 4.2 日志字段（统一格式）

```
trace_id, parent_id, timestamp, actor(user_id, dept, ip, device, client),
action, resource(type, id, name), permission_decision(allow/deny, reason),
model_info, cost, result_status, confirm_info(by_whom, at), data_masked(bool)
```

### 4.3 审计能力

- 按人 / 部门 / 时间 / 操作类型 / trace_id 多维检索
- 一次任务可**完整回放**（用户问什么 → 检索了什么 → 调了哪些工具 → 谁确认 → 结果）
- 导出报表（合规检查用）
- 异常检测告警：短时间大量导出、非工作时间批量操作、越权尝试

### 4.4 保留与合规

- 保留期按公司合规要求设定（常见 6 个月 ~ 3 年）
- 审计日志**只追加、不可篡改**（WORM 存储或链式哈希）
- 日志本身脱敏，避免成为新的泄露面
- 明确告知员工「使用 Agent 的行为会被记录」（合法性要求）

## 5. 管理控制台

平台管理员与部门管理员共用一个后台，按角色显隐：

| 模块 | 平台管理员 | 部门管理员 |
|---|---|---|
| 用户与组织 | ✅ | 只读本部门 |
| 角色与能力 | ✅ | 本部门成员能力申请 |
| 模型与路由 | ✅ | ❌ |
| 配额与成本 | ✅ 全局 | ✅ 本部门 |
| 知识库 | ✅ | ✅ 本部门 |
| 技能与模板 | ✅ | ✅ 本部门 |
| 连接器 | ✅ 全局 | 申请开通 |
| 审计日志 | ✅ | 本部门只读 |
| 系统监控 | ✅ | ❌ |
