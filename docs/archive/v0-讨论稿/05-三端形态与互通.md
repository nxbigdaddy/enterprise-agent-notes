# 05 · 三端形态与互通

> 版本：v0.1（草稿） · 对应需求：「桌面端和 Web 端互通，移动端通过企微浏览器（企微中建立应用为入口），三端数据互通」

## 1. 核心原则

> **服务端是唯一事实源；三端都只是「视图 + 本机能力代理」。**

推论：

- 会话、消息、上下文、文件元数据、待办、通知、权限——全部服务端存储，三端拉取。
- 客户端只保留**缓存**（可丢、可重建）和**本机专属状态**（本地路径、窗口位置、设备信息）。
- **不做客户端间 P2P 同步**，一律经服务端中转，否则冲突与权限都无法收敛。

## 2. 三端能力矩阵

| 能力 | Web 端 | 桌面端 | 移动端（企微 H5） |
|---|---|---|---|
| 对话问答 | ✅ | ✅ | ✅ |
| 知识库检索 | ✅ | ✅ | ✅ |
| 文档生成与下载 | ✅ | ✅ | ⚠️ 仅预览，下载受企微限制 |
| 邮件 | ✅ | ✅ | ⚠️ 摘要/拟稿/审批，长文编辑弱 |
| 日程会议 | ✅ | ✅ | ✅ |
| 待办与通知 | ✅ | ✅ + 系统通知 | ✅ + 企微推送 |
| 工作流/定时任务 | ✅ 配置 | ✅ 配置 | ⚠️ 仅查看与确认 |
| **本机文件读写** | ❌ | ✅ | ❌ |
| **本地系统连接** | ❌ | ✅ | ❌ |
| 剪贴板/截图/拖拽 | ⚠️ 浏览器受限 | ✅ | ❌ |
| 全局快捷键/悬浮窗 | ❌ | ✅ | ❌ |
| 后台长任务常驻 | ❌ | ✅ | ❌ |
| 生物识别/免登 | ❌ | ⚠️ | ✅ 企微免登 |
| 离线可用 | ❌ | ⚠️ 只读缓存 | ❌ |

**结论**：Web 端是「全功能但无本机能力」；桌面端是「Web 全部能力 + 本机能力」；移动端是「轻交互 + 审批确认 + 通知接收」。

## 3. 三端互通的具体机制

### 3.1 会话跨端续接

- 会话在服务端有唯一 `conversation_id`。
- 用户在桌面端发起、出门用手机继续 —— 打开即看到完整上下文。
- 需要「端感知」的信息单独存：如附带的本机文件在移动端显示为「来自桌面端的本地文件（不可用）」并给出重新上传入口。
- 正在流式生成的回答：其他端显示「生成中」，完成后补全。

### 3.2 文件跨端流转

```
桌面端选本机文件 → 用户确认上传 → 对象存储(带权限) → 三端可访问
移动端拍照/上传 → 云端 → 桌面端可下载到指定目录
```

要求：

- 上传前**明示**：哪个文件、多大、去哪儿、谁能看。
- 默认**不上传**：只有用户显式提交的那一份才上传。
- 大文件走分片上传 + 断点续传 + 秒传（hash 去重）。
- 权限随文件走，下载走**临时签名 URL**，不用公开链接。

### 3.3 桌面端 ↔ 云端通信

| 通道 | 用途 | 说明 |
|---|---|---|
| HTTPS 短连接 | 常规 API | 简单可靠 |
| WebSocket 长连接 | 服务端主动下发（工具调用指令、通知、任务状态） | 桌面端必需，支持断线重连 |
| 轮询兜底 | 长连接不可用时 | 降级方案 |

**关键设计**：服务端不能直接访问用户本机。所有本机操作都是「服务端下发指令 → 本地代理执行 → 回报结果」，且本地代理**对每条指令做本地策略校验**（目录白名单、危险操作拦截）后才执行。

### 3.4 通知与触达

| 场景 | 触达方式 |
|---|---|
| 任务完成（长任务） | 桌面系统通知 + 站内信 + 企微应用消息 |
| 需要人工确认 | 当前端弹窗 + 其他端红点 + 企微推送（可选） |
| 定时汇总 | 企微应用消息（移动端首选） |
| 安全告警 | 管理员企微 + 邮件 |

统一走**通知中心**，由服务端决定触达哪些端，避免各端各自实现。

## 4. 移动端（企微入口）专项

### 4.1 接入方式

- 在企业微信管理后台创建**自建应用**，配置可信域名、JS-SDK 权限、可见范围。
- 移动端以 **H5（企微内置浏览器）** 访问，使用企微 OAuth 免登获取 `userid`。
- 企微工作台作为入口卡片；同时支持从聊天/群消息中打开。

### 4.2 企微内置浏览器的限制（必须提前知道）

| 限制 | 影响 | 应对 |
|---|---|---|
| 无文件系统访问 | 无法做本机文件管理 | 只做云端文件，或调用企微选文件 API |
| 上传/下载受限 | 大文件下载体验差 | 优先在线预览；下载走企微 JS-SDK |
| 不能后台常驻 | 长任务会因切后台中断 | **任务一律在服务端跑**，完成后推送 |
| WebView 版本差异 | 部分 API 不支持 | 特性检测 + 降级；前端做兼容矩阵 |
| 存储空间小 | 缓存易被清 | 不依赖本地存储 |
| 无系统通知权限 | 提醒弱 | 走企微应用消息推送 |
| 屏幕小 | 复杂交互不可用 | 移动端只做「读 + 确认 + 轻操作」 |
| 页面跳出受限 | 外链需配可信域名 | 统一域名 + 白名单配置 |

### 4.3 移动端设计原则

1. **任务在云端执行，手机只做发起与查看**。
2. **确认类交互优先**：审批、发送邮件、确认结果，这些在手机上最合适。
3. **卡片式消息**：企微应用消息用模板卡片，可直接在企微内操作（如「同意/拒绝」）。
4. **不为移动端做功能对齐**，做「场景对得上的最小集」。

## 5. 端与账号的绑定

| 项 | 方案 |
|---|---|
| 统一身份 | 三端同一 `user_id`（来自企微通讯录） |
| 会话隔离 | 各端独立 session，可通过「我的设备」查看与远程下线 |
| 桌面端设备绑定 | 首次扫码，绑定设备指纹；上限 N 台（待定，建议 2） |
| 移动端 | 免登，无需绑定 |
| 异常登录 | 新设备/新 IP 触发通知 |

## 6. 用户体验一致性

- **共享组件库**：Web 与桌面端同构（React），移动端独立轻量版本。
- **一致的会话体验**：三端能看到同一会话列表、同一历史。
- **一致的权限提示**：无权限时提示文案与申请入口统一。
- **状态可见**：任何长任务在三端都显示同一状态机（排队/执行中/待确认/完成/失败）。

## 7. 待确认问题

1. 桌面端是否需要「关闭窗口后继续在后台跑任务」？（建议：是，托盘常驻 + 可退出）
2. 移动端是否需要小程序版本以补充 H5 能力？（如扫码、拍照体验）
3. 三端是否需要同一时间只能一处活跃（防止上下文串扰）？（建议：不限制，但互相同步）
4. 企微应用的可见范围如何分批放开？
5. 外网访问（员工在家）如何处理？VPN / 反向代理 / 公网网关 + 强认证？
