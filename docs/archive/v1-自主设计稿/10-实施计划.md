### 2.1 建议的并行方式（3 人）

| 角色 | 负责 |
|---|---|
| **后端 A** | 任务 1、6（邮件 + 知识库集成） |
| **后端 B** | 任务 4、5、7、8（骨架 + 网关 + 审计 + 部署） |
| **前端** | 任务 3（并提前对接 API 契约） |
| 共享 | 任务 2（谁有空谁做，接口先定） |

> **API 契约先行**：第 1 周就冻结 OpenAPI，前端可并行开发，减少联调阻塞。

## 4. 前置条件与开工检查表

> 这些不受研发团队完全控制，**第 1 周必须全部启动**。

| # | 事项 | 负责方 | 阻塞 | 预估周期 | 状态 |
|---|---|---|---|---|---|
| **V1** | 邮件系统能否拿到 API / IMAP 权限 | IT / 邮件管理员 | 邮件摘要场景 | 1~2 周 | ☐ |
| **V2** | 企微自建应用创建 + 通讯录读取权限 + 回调域名 | IT | 登录与组织同步 | 1~3 周 | ☐ |
| **V3** | 数据出境结论（能否用外部模型 API） | 安全 / 法务 | 模型路线 | 不确定 | ☐ |
| **V4** | MaxKB 专业版开放 API 验证（§7 的 V1~V4） | 研发 + 原厂 | 知识问答场景 | 3~5 天 | ☐ |
| **V5** | **知识库有可用内容且有责任人** | 业务 | 知识问答质量 | 立即 | ☐ |
| V6 | GPU 采购或外部 API 额度 | 采购 | 内网模型能力 | 1~3 个月 | ☐ |
| V7 | 试点部门与 3 个场景确认 | 业务 | 全部排期 | 立即 | ☐ |

**V1 与 V4 是最可能卡住两项**：
- 如果 V1 失败（邮件 API 拿不到）→ MVP 需替换第三个场景。
- 如果 V4 失败（MaxKB API 不满足）→ 退回 `PgVectorRetriever` 自建，MVP +3~4 人周。

## 7. MaxKB 集成验证清单（M0 必做）

| # | 验证项 | 方法 | 不通过的应对 |
|---|---|---|---|
| V4-1 | 开放 API 支持**建库 / 上传文档 / 检索** | 用 Postman / curl 各调一次 | 切 `PgVectorRetriever` 自建 |
| V4-2 | 检索 API 返回**引用来源与片段** | 检查响应字段 | 需额外设计引用方案 |
| V4-3 | 模型端点可配**自定义 OpenAI 兼容地址** | 在后台改配置并验证请求确实经过我们的网关 | 统一出口红线被破坏，需评估 |
| V4-4 | 服务账号调用**不依赖其用户体系** | 用纯 API Key 调用，不带任何 MaxKB 用户身份 | B3 失效，双份组织同步问题回归 |

## 8. 验收标准（M3）

| 类别 | 标准 |
|---|---|
| 功能 | 三个场景端到端可用 |
| 质量 | 知识问答引用正确率 ≥ 85%；幻觉率 ≤ 5% |
| 安全 | **越权测试全部通过**；敏感信息外发 0 起 |
| 审计 | 任一请求可由 `trace_id` 完整回放 |
| 性能 | 首字延迟 ≤ 3s；完整回答 ≤ 15s |
| 成本 | 单活跃用户月成本 ≤ 设定上限，可核算 |
| 稳定 | 连续运行 1 周无 P0 故障 |
| 可用性 | 模型不可用时系统降级而非整体不可用 |
