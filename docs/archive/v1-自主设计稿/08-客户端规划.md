# 08 · 客户端规划

> 版本：v1.0 · MVP 只做 Web 端；桌面端与企微 H5 为 P1

---

## 1. 三端能力矩阵

| 能力 | Web（P0） | 桌面端（P1） | 企微 H5（P1） |
|---|---|---|---|
| 对话问答 | ✅ | ✅ | ✅ |
| 知识检索 | ✅ | ✅ | ✅ |
| 文档生成与下载 | ✅ | ✅ | ⚠️ 仅预览 |
| 邮件查看与摘要 | ✅ | ✅ | ⚠️ 摘要为主 |
| 待办与通知 | ✅ | ✅ + 系统通知 | ✅ + 企微推送 |
| 会话历史 | ✅ | ✅ | ✅ |
| **本机文件读写** | ❌ | ✅ | ❌ |
| **本地系统连接** | ❌ | ✅ | ❌ |
| 剪贴板 / 截图 / 拖拽 | ⚠️ 浏览器受限 | ✅ | ❌ |
| 全局快捷键 / 悬浮窗 | ❌ | ✅ | ❌ |
| 后台长任务常驻 | ❌ | ✅ | ❌ |
| 免登 | 扫码 | 首次扫码后免登 | 企微免登 |

**结论**：Web 是「全功能但无本机能力」；桌面端是「Web 全部能力 + 本机能力」；H5 是「轻交互 + 确认 + 通知接收」。

## 2. Web 端（P0）

### 2.1 技术

| 项 | 选择 |
|---|---|
| 框架 | React 18 + TypeScript + Vite |
| UI | Ant Design 5 |
| 状态 | React 内置（useState / Context）；**页面 > 15 个再引入状态库** |
| 请求 | `fetch` + 轻封装（统一鉴权、错误、重试） |
| 流式 | **SSE**（`EventSource` 或 `fetch` + `ReadableStream`） |
| Markdown | `markdown-it` + 代码高亮 |
| 文件预览 | PDF.js / docx-preview（按需） |
| 类型 | 从后端 OpenAPI 生成（见 §5） |

### 2.2 页面（MVP）

| 页面 | 内容 |
|---|---|
| 登录 | 企微扫码 |
| 会话主界面 | 左侧会话列表 · 中间对话流 · 右侧引用面板 |
| 知识问答 | 复用会话界面，展示引用卡片 |
| 邮件 | 邮件列表（分类/优先级）· 摘要详情 · 每日汇总 |
| 文档生成 | 材料选择/上传 · 模板选择 · 预览 · 导出 |
| 我的 | 账号信息、用量（token/成本）、退出 |

**P1 增加**：管理后台（用户/角色/配额/审计/知识库映射）。

### 2.3 SSE 约定

```
GET  /api/v1/chat/stream?conversation_id=...
事件类型：
  event: delta      data: {"text": "..."}         # 增量文本
  event: refs       data: {"refs": [...]}          # 引用（在答案前或后）
  event: done       data: {"trace_id":"...", "usage":{...}}
  event: error      data: {"code":"...", "message":"..."}
```

- **不用 WebSocket 做流式**：SSE 更简单，天然支持断线重连与代理透传。
- WebSocket 仅在 P1 桌面端需要服务端主动下发时引入。

## 3. 桌面端（P1）

### 3.1 技术选型

**Electron 30+ + Node 20 LTS**，复用 Web 端 React 代码。

| 项 | 选择 |
|---|---|
| 打包 | electron-builder |
| 更新 | electron-updater + 内网更新服务器 |
| 本地存储 | SQLite（better-sqlite3）存本地索引与操作日志 |
| 文件监听 | chokidar |
| 安全 | `contextIsolation: true` + `nodeIntegration: false` + 白名单 IPC |

**为什么不用 Tauri**：本地能力重（文件 + 本地系统 + Office 解析），Node 生态现成；Tauri 要写 Rust 且依赖系统 WebView，信创适配不确定。
**为什么不用 Python GUI（PyQt）**：无法与 Web 端复用任何代码，等于多做一套。

### 3.2 本机能力边界

| 能力 | MVP（P1 阶段） |
|---|---|
| 授权目录（用户显式添加的目录白名单） | ✅ 核心 |
| 系统敏感目录黑名单（永久禁止授权） | ✅ 核心 |
| 文件读取（只读） | ✅ |
| 文件写入（生成文档落盘） | ✅ 需确认 |
| 删除 | ❌ 不提供（P2 再说，且必须逐次确认 + 进回收站） |
| 文件索引 | 只做文件名索引；**内容索引可选且需用户显式开启** |

**安全约束（评审必查）**：
1. **默认零授权**——用户显式添加目录才能访问
2. **不上传未确认的内容**——上传前展示清单（哪个文件、多大、去哪）
3. **只出站，不开监听端口**
4. **本机操作日志用户可见可导出**
5. **凭据存系统密钥库**（DPAPI / Keychain），不落明文
6. **卸载时清理本地缓存、索引与凭据**

### 3.3 本地系统连接（P2）

**用 Python sidecar 补齐 Node 的短板**，且**按需引入**——只有出现下列需求才挂：

| 需求 | 为什么 Node 做不了 |
|---|---|
| COM / Office 自动化（驱动 Excel/Word/Outlook） | Node 原生扩展 ABI 与 Electron 强耦合，`ffi-napi` 长期缺维护 |
| Windows UI Automation（操作老 C/S 客户端） | 只能模拟输入，拿不到控件树 |
| 厂商硬件 DLL（U 盾、读卡器、加密狗） | 需 `ctypes` 级能力 |
| 本地 OCR / ML | Node 无对等生态 |

**推荐做法**：把本地插件协议做成 **MCP 兼容 + stdio 传输**，则 Python sidecar 天然就是一个本地 MCP Server，不需要另造协议。

> ⚠️ **不要默认引入 sidecar**：它带来体积（+40MB 起，带 OCR 可达 300MB+）、冷启动（1~3s）、杀软误报（PyInstaller 产物需代码签名）三项成本。

## 4. 移动端 · 企微 H5（P1）

### 4.1 接入方式

- 在企业微信管理后台创建**自建应用**，配置可信域名、JS-SDK 权限、可见范围
- 以 **H5（企微内置浏览器）** 访问，企微 OAuth 免登获取 `userid`
- 企微工作台作为入口卡片

### 4.2 内置浏览器的限制（必须提前知道）

| 限制 | 影响 | 应对 |
|---|---|---|
| 无文件系统访问 | 不能做本机文件管理 | 只做云端文件；或调企微选文件 API |
| 上传/下载受限 | 大文件下载体验差 | 优先在线预览 |
| **不能后台常驻** | 长任务会因切后台中断 | **任务一律在服务端跑**，完成后推送 |
| WebView 版本碎片化 | 部分 API 不支持 | 特性检测 + 降级 |
| 存储空间小 | 缓存易被清 | 不依赖本地存储 |
| 无系统通知权限 | 提醒弱 | 走企微应用消息（模板卡片） |
| 屏幕小 | 复杂交互不可用 | 只做「读 + 确认 + 轻操作」 |

### 4.3 设计原则

1. **任务在云端执行，手机只做发起与查看**
2. **确认类交互优先**（审批、确认结果）
3. **卡片式消息**——企微应用消息用模板卡片，可直接在企微内操作
4. **不为移动端做功能对齐**，做「场景对得上的最小集」

## 5. 跨端一致性

| 机制 | 做法 |
|---|---|
| **类型共享** | 后端 FastAPI → OpenAPI → `openapi-typescript` → 前端 `types/` |
| **会话一致** | 会话在服务端有唯一 `conversation_id`，三端拉同一份数据 |
| **状态一致** | 长任务在三端显示同一状态机（排队/执行中/完成/失败） |
| **权限提示一致** | 无权限时文案与申请入口统一 |
| **客户端识别** | 请求头带 `X-Client: web / desktop / h5`，写入审计 |

> **触发 Monorepo 的条件**：当第二个客户端（桌面端或 H5）启动时，把 `packages/ui`、`packages/types`、`packages/api-sdk` 抽出来。**MVP 阶段用单工程 + 生成的 types 即可，不要提前上 Monorepo。**

## 6. 明确不做

| 不做 | 原因 |
|---|---|
| 原生移动 App（React Native / Flutter） | 企微入口已解决分发、免登、推送三个最难的问题 |
| 移动端完整功能对齐 | 企微内置浏览器能力受限 |
| 桌面端 RPA / 浏览器自动化 | 老系统适配是无底洞，P3 再说 |
| 默认引入 Python sidecar | 体积、启动、杀软三重成本 |
| 自研组件库 | AntD 已覆盖 |
