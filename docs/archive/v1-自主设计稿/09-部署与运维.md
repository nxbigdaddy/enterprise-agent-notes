# 09 · 部署与运维

> 版本：v1.0 · 目标：单节点支撑 < 500 用户

---

## 1. 部署拓扑（Tier 0）

```
                    ┌───────────── 用户 ─────────────┐
                    │        HTTPS（443）             │
                    └───────────────┬────────────────┘
┌───────────────────────────────────▼──────────────────────────┐
│  应用节点  8C 16G                                              │
│  ┌──────────┐  ┌────────────────────┐  ┌──────────────────┐  │
│  │  Nginx   │─▶│  app (uvicorn ×4)  │  │ scheduler        │  │
│  │ 443/80   │  │  FastAPI           │  │ (APScheduler)    │  │
│  └──────────┘  └────────────────────┘  └──────────────────┘  │
│                        │                       │              │
│                        └───────────┬───────────┘              │
│                                    ▼                          │
│                        本地卷 /data/storage                   │
└────────────────────────────────────┬──────────────────────────┘
                                     │ 5432（仅内网）
┌────────────────────────────────────▼──────────────────────────┐
│  数据库节点  8C 16G                                            │
│  PostgreSQL 16（主）                                           │
└───────────────────────────────────────────────────────────────┘

外部依赖：MaxKB 专业版（独立部署）· 模型 API（出网白名单）
```

**3 个容器**：`nginx` · `app` · `postgres`（scheduler 与 app 同镜像不同启动命令）。
**起步可压到单台 8C16G**（应用 + 数据库同机），用于 PoC 与首批试点。

## 2. 环境要求

| 项 | 要求 |
|---|---|
| OS | Linux（Ubuntu 22.04 / Rocky 9 等） |
| Docker | 24+ 与 Docker Compose v2 |
| CPU / 内存 | 应用 8C16G；数据库 8C16G（试点期可合并为单机 8C16G） |
| 磁盘 | 系统 50G + 数据卷（预估：DB 50G，文件卷按需，起步 200G） |
| 网络 | 应用可访问：PostgreSQL、MaxKB、模型 API（出网白名单） |
| 出网 | **仅 `app` 可出网**，且只能到 `AIGateway` 配置的模型端点 |
| 域名与证书 | 一个内网域名 + TLS 证书（企微回调要求 HTTPS） |
| 时区 | 容器统一 UTC，展示层转本地 |

## 3. 配置与密钥

| 类别 | 方式 |
|---|---|
| 普通配置 | `.env` + `sys_config` 表（可热更新，如模型路由、配额默认值） |
| 密钥 | **Docker Secret / 环境变量**；数据库只存 `credential_ref`，**不落明文** |
| 涉及的密钥 | 企微 CorpID/Secret · 邮件 API 凭据 · 模型 API Key · MaxKB 服务账号 · JWT 签名密钥 |
| 代码库 | **禁止**提交任何密钥；`.env.example` 只放占位符 |

**配置分层**：环境变量（部署级，改动需重启）→ `sys_config` 表（运行级，热更新）。
**不引入配置中心**——单节点不需要。

## 4. CI/CD

| 阶段 | 做法 |
|---|---|
| 代码质量 | pre-commit：Ruff + mypy |
| 测试 | pytest（单测 + 关键路径集成测试） |
| 构建 | Docker 镜像构建，打 Git SHA 标签 |
| 部署 | `docker compose pull && docker compose up -d`（可加一个 `deploy.sh`） |
| 回滚 | 切回上一个镜像标签 |
| 环境 | `dev`（本地 Compose）· `staging`（可选）· `prod` |

> **MVP 不需要复杂流水线**。用公司现有的 GitLab CI 或一个 Makefile 即可，重点是**镜像可回滚**。

## 5. 监控（Tier 0：最小可用）

不引入 Prometheus / Grafana，靠 DB 与日志：

| 关注点 | 手段 |
|---|---|
| 应用日志 | structlog JSON → stdout → `docker logs` |
| 错误追踪 | 日志中 `level=error` + `trace_id` |
| **成本与用量** | `ai_call_log` + `quota` 表，管理端出报表 |
| 任务健康 | `job` 表：`status` 与 `attempts`；失败任务查询 |
| 邮件同步 | `mail_account.last_sync_at` 是否停滞 |
| 服务存活 | `/health` 端点 + 外部简单探活 |
| 磁盘水位 | 定时检查并告警 |

**四个必须告警的阈值**：

| 指标 | 阈值 | 手段 |
|---|---|---|
| 模型调用失败率 | > 10%（5 分钟窗口） | 企微机器人 |
| 配额使用率 | > 80% | 企微机器人 |
| 任务失败数 | 连续失败 > 10 | 企微机器人 |
| 磁盘使用率 | > 85% | 企微机器人 |

> Tier 1（有运维投入时）再引入 Prometheus + Grafana + Loki，见 `03-技术栈.md` §4。

## 6. 备份与恢复

| 对象 | 方式 | 频率 | 保留 |
|---|---|---|---|
| PostgreSQL | `pg_dump` 逻辑备份 | 每日 | 30 天 |
| PostgreSQL | WAL 归档 | 持续 | 7 天 |
| 本地文件卷 | `rsync` / `restic` 增量 | 每日 | 30 天 |
| 配置 | `.env` 与 Secret 的加密副本 | 变更时 | 永久 |

**恢复演练**：每季度做一次全量恢复，记录 RTO/RPO 实测值。

| 指标 | 目标 |
|---|---|
| RPO（可容忍数据丢失） | ≤ 24 小时（WAL 归档可到分钟级） |
| RTO（恢复时间） | ≤ 4 小时 |

> ⚠️ **本地文件卷是 Tier 0 最薄弱的一环**——没有副本，备份就是唯一保障。这也是"何时引入 MinIO"的触发条件之一。

## 7. 升级与回滚

```
1. 备份数据库与文件卷
2. 拉取新镜像
3. 执行 Alembic 迁移（向前兼容，不做破坏性变更）
4. docker compose up -d
5. 健康检查 + 冒烟测试
6. 失败 → 切回旧镜像 + 回滚迁移（若需要）
```

**迁移原则**：任何迁移必须**向前兼容**（先加字段，不删不改；下个版本再清理）。

---

## 8. 容量与扩容触发

| 观察指标 | 阈值 | 动作 |
|---|---|---|
| 应用 CPU | 持续 > 70% | 应用节点加 1 台 + 引入 Redis（会话/限流共享） |
| 应用节点数 | > 1 | **必须引入 Redis**（否则限流与缓存失效） |
| 任务积压 | `job` 中 pending > 1000 | 引入 Celery + 独立 worker |
| 磁盘使用 | > 100GB 文件 | 引入 MinIO / S3 |
| PG 连接数 | 持续 > 80% | 加连接池（pgbouncer）或升配 |
| 日常模型成本 | 超预算 | 调整路由，把低价值场景切到便宜模型 |

**扩容顺序**：先加应用节点（+ Redis）→ 再拆数据库（读写分离/升配）→ 最后考虑对象存储与任务队列独立。

## 9. 安全运维清单

| # | 项 |
|---|---|
| 1 | 数据库不对公网暴露，仅应用节点可连 |
| 2 | 出网白名单只放模型端点与必要服务 |
| 3 | 容器以非 root 运行 |
| 4 | 镜像定期扫描漏洞 |
| 5 | Secret 不进镜像、不进 Git |
| 6 | Nginx 限流（防刷） |
| 7 | 登录失败次数限制 |
| 8 | 审计日志只追加，应用账号无 DELETE 权限 |
| 9 | 定时任务幂等（`job.idempotency_key`） |
| 10 | `/health` 不暴露内部细节 |
