# 04 · 数据模型

> 版本：v1.0 · 目标数据库：PostgreSQL 16

---

## 1. 设计约定

| 项 | 约定 |
|---|---|
| 主键 | `bigserial`（自增） |
| 时间 | `timestamptz`，统一 UTC 存储，展示时转本地 |
| 软删除 | 关键业务表用 `deleted_at timestamptz`，其余物理删除 |
| 命名 | 表名单数 snake_case；外键 `<表名>_id`；布尔 `is_*` / `has_*` |
| JSON | 非结构化扩展字段用 `jsonb`，**不要滥用**（能建模就建模） |
| 审计字段 | 关键表带 `created_at` / `updated_at`；`updated_by` 按需 |
| 迁移 | 全部由 Alembic 管理，禁止手改生产库 |

## 3. 组织与账号

```sql
CREATE TABLE dept (
  id            bigserial PRIMARY KEY,
  wx_dept_id    text UNIQUE,              -- 企微部门 ID，组织事实源的锚点
  name          text NOT NULL,
  parent_id     bigint REFERENCES dept(id),
  path          text NOT NULL,            -- 物化路径 '1/12/135/'，便于子树查询
  sort_order    int  DEFAULT 0,
  is_active     boolean DEFAULT true,
  synced_at     timestamptz
);

CREATE TABLE "user" (
  id             bigserial PRIMARY KEY,
  wx_userid      text UNIQUE NOT NULL,    -- 企微 UserID = 我们的登录锚点
  name           text NOT NULL,
  email          text,
  mobile         text,
  avatar_url     text,
  primary_dept_id bigint REFERENCES dept(id),
  data_level_max smallint DEFAULT 1,      -- 该用户可见的最高密级
  status         text DEFAULT 'active',   -- active / disabled
  last_login_at  timestamptz,
  created_at     timestamptz DEFAULT now(),
  updated_at     timestamptz DEFAULT now()
);

CREATE TABLE user_dept (            -- 兼职部门，支持跨部门协作
  user_id  bigint REFERENCES "user"(id),
  dept_id  bigint REFERENCES dept(id),
  is_primary boolean DEFAULT false,
  PRIMARY KEY (user_id, dept_id)
);
```

> `status='disabled'` 时，该用户所有会话与 token 立即失效（离职处理）。

## 4. 权限

```sql
CREATE TABLE role (
  id      bigserial PRIMARY KEY,
  code    text UNIQUE NOT NULL,      -- employee / dept_admin / platform_admin / auditor
  name    text NOT NULL,
  is_builtin boolean DEFAULT false
);

CREATE TABLE user_role (
  user_id  bigint REFERENCES "user"(id),
  role_id  bigint REFERENCES role(id),
  scope_dept_id bigint REFERENCES dept(id),  -- 部门管理员的作用域；平台角色为 NULL
  PRIMARY KEY (user_id, role_id, scope_dept_id)
);

-- 能力字典：系统启动时按代码里的声明同步进库，便于后台展示
CREATE TABLE capability (
  code        text PRIMARY KEY,      -- 如 mail.send / kb.manage / file.write
  name        text NOT NULL,
  group_name  text,
  risk_level  text,                  -- low / medium / high
  description text
);

CREATE TABLE role_capability (
  role_id         bigint REFERENCES role(id),
  capability_code text REFERENCES capability(code),
  granted         boolean DEFAULT true,
  PRIMARY KEY (role_id, capability_code)
);

-- 用户级覆盖：个别开通或收回，优先级高于角色
CREATE TABLE user_capability (
  user_id         bigint REFERENCES "user"(id),
  capability_code text REFERENCES capability(code),
  granted         boolean NOT NULL,
  reason          text,
  expires_at      timestamptz,       -- 临时授权可设置过期
  granted_by      bigint REFERENCES "user"(id),
  created_at      timestamptz DEFAULT now(),
  PRIMARY KEY (user_id, capability_code)
);

-- 数据范围规则：决定「能看哪些数据」
CREATE TABLE data_scope_rule (
  id            bigserial PRIMARY KEY,
  subject_type  text NOT NULL,       -- role / user
  subject_id    bigint NOT NULL,
  resource_type text NOT NULL,       -- kb / mail / attachment / conversation
  scope_type    text NOT NULL,       -- self / dept / dept_tree / all
  dept_id       bigint REFERENCES dept(id),
  data_level_max smallint,
  enabled       boolean DEFAULT true
);
```

**权限判定顺序（服务端，每次请求实时计算，不缓存决策）**：

```
1. 用户是否 active？否 → 拒绝
2. user_capability 覆盖？有则用它
3. role_capability 聚合？任一角色 granted → 允许
4. 数据是否在 data_scope_rule 允许范围内？且 data_level ≤ 用户上限？
5. 全部通过 → 允许，并记录 decision 到 audit_log
```

## 5. 会话与文件

```sql
CREATE TABLE conversation (
  id         bigserial PRIMARY KEY,
  user_id    bigint REFERENCES "user"(id),
  title      text,
  scene      text,                  -- kb_qa / mail / doc / general
  is_archived boolean DEFAULT false,
  created_at timestamptz DEFAULT now(),
  updated_at timestamptz DEFAULT now()
);

CREATE TABLE message (
  id              bigserial PRIMARY KEY,
  conversation_id bigint REFERENCES conversation(id) ON DELETE CASCADE,
  role            text NOT NULL,    -- user / assistant / system / tool
  content         text,
  refs            jsonb,            -- 引用来源：[{kb_id, doc_name, chunk_id, score, snippet}]
  tool_calls      jsonb,
  trace_id        text,
  tokens_in       int,
  tokens_out      int,
  created_at      timestamptz DEFAULT now()
);
CREATE INDEX ON message (conversation_id, created_at);

CREATE TABLE attachment (
  id          bigserial PRIMARY KEY,
  owner_id    bigint REFERENCES "user"(id),
  filename    text NOT NULL,
  size        bigint,
  mime        text,
  storage_key text NOT NULL,        -- 本地卷相对路径；将来换 S3 只改这里
  sha256      text,                 -- 去重与秒传
  source      text,                 -- upload / generated / mail
  created_at  timestamptz DEFAULT now()
);
```

## 6. AI 相关

```sql
CREATE TABLE model_provider (
  id            bigserial PRIMARY KEY,
  name          text NOT NULL,       -- 展示名，如「内网 Qwen」「外部 A」
  type          text NOT NULL,       -- external / internal
  base_url      text NOT NULL,       -- OpenAI 兼容端点
  credential_ref text,               -- 指向密钥存储的 key，不存明文
  data_level_max smallint,           -- 该通道允许承载的最高密级
  is_enabled    boolean DEFAULT true,
  health        text DEFAULT 'unknown'
);

CREATE TABLE model_route (
  id             bigserial PRIMARY KEY,
  scene          text NOT NULL,      -- kb_qa / mail_summary / doc_gen / default
  data_level     smallint,           -- NULL 表示不限
  primary_model  text NOT NULL,      -- provider_id + model 名
  fallback_chain jsonb,              -- ["provider:model", ...]
  priority       int DEFAULT 100,
  is_enabled     boolean DEFAULT true
);

-- 每次模型调用的台账：成本与审计的唯一依据
CREATE TABLE ai_call_log (
  id           bigserial PRIMARY KEY,
  trace_id     text NOT NULL,
  user_id      bigint REFERENCES "user"(id),
  dept_id      bigint,
  scene        text,
  provider_id  bigint,
  model        text,
  data_level   smallint,
  route_reason text,                 -- 为什么选了这个模型（审计要能回答）
  tokens_in    int,
  tokens_out   int,
  cost         numeric(12,6),
  latency_ms   int,
  is_cached    boolean DEFAULT false,
  is_degraded  boolean DEFAULT false,
  status       text,                 -- ok / error
  error_code   text,
  created_at   timestamptz DEFAULT now()
);
CREATE INDEX ON ai_call_log (user_id, created_at);
CREATE INDEX ON ai_call_log (dept_id, created_at);
CREATE INDEX ON ai_call_log (trace_id);

CREATE TABLE quota (
  id          bigserial PRIMARY KEY,
  scope       text NOT NULL,         -- user / dept
  target_id   bigint NOT NULL,
  period      text NOT NULL,         -- day / month
  limit_tokens bigint,
  limit_cost   numeric(12,2),
  used_tokens  bigint DEFAULT 0,
  used_cost    numeric(12,2) DEFAULT 0,
  period_start timestamptz,
  is_blocked   boolean DEFAULT false,
  UNIQUE (scope, target_id, period, period_start)
);

CREATE TABLE prompt_template (
  id       bigserial PRIMARY KEY,
  scene    text NOT NULL,
  version  int  NOT NULL,
  content  text NOT NULL,
  status   text DEFAULT 'draft',     -- draft / active / archived
  created_by bigint,
  created_at timestamptz DEFAULT now(),
  UNIQUE (scene, version)
);
```

## 7. 知识库映射（MaxKB 集成的关键）

**MaxKB 是权威的知识库与文档存储**，我们只存**映射与授权关系**，不复制内容。

```sql
CREATE TABLE kb_registry (
  id            bigserial PRIMARY KEY,
  maxkb_kb_id   text UNIQUE NOT NULL,   -- MaxKB 中的知识库 ID（外部键）
  name          text NOT NULL,
  kb_type       text NOT NULL,          -- dept / common / special
  owner_dept_id bigint REFERENCES dept(id),
  data_level    smallint DEFAULT 1,
  is_enabled    boolean DEFAULT true,
  synced_at     timestamptz
);

-- 「谁能查这个库」——这是我们自己的授权，不依赖 MaxKB 的权限模型
CREATE TABLE kb_grant (
  id           bigserial PRIMARY KEY,
  kb_id        bigint REFERENCES kb_registry(id) ON DELETE CASCADE,
  subject_type text NOT NULL,           -- dept / role / user / all
  subject_id   bigint,
  granted      boolean DEFAULT true,
  UNIQUE (kb_id, subject_type, subject_id)
);
```

**检索时的 kb_id 计算**：

```
可查 kb_id 列表 =
    kb_grant 中 subject 命中当前用户（或其部门及其子树 / 其角色 / 本人）的库
  ∩ kb_registry.is_enabled = true
  ∩ kb_registry.data_level ≤ user.data_level_max
```

> ⚠️ 这个列表**只由服务端计算**，客户端传来的 kb_id 一律忽略。这是架构红线 R4。

## 8. 邮件

```sql
CREATE TABLE mail_account (
  id           bigserial PRIMARY KEY,
  user_id      bigint REFERENCES "user"(id),
  provider     text NOT NULL,        -- graph / imap / ews —— 只会有实际的那一种
  email        text NOT NULL,
  auth_ref     text,                 -- 凭据引用，加密存储
  status       text DEFAULT 'active',
  sync_state   jsonb,                -- deltaToken / UIDVALIDITY 等增量同步游标
  last_sync_at timestamptz,
  UNIQUE (user_id, email)
);

CREATE TABLE mail_message (
  id            bigserial PRIMARY KEY,
  account_id    bigint REFERENCES mail_account(id) ON DELETE CASCADE,
  remote_id     text NOT NULL,       -- 以 Message-ID 去重
  thread_id     text,
  subject       text,
  from_addr     text,
  to_addrs      text[],
  received_at   timestamptz,
  snippet       text,
  has_attachment boolean DEFAULT false,
  category      text,                -- 规则分类结果
  priority      smallint,            -- 规则+模型打分
  summary       text,                -- 模型摘要（缓存，避免重复调用）
  todos         jsonb,               -- 抽取出的待办
  processed_at  timestamptz,
  created_at    timestamptz DEFAULT now(),
  UNIQUE (account_id, remote_id)
);
CREATE INDEX ON mail_message (account_id, received_at DESC);

CREATE TABLE mail_attachment (
  id         bigserial PRIMARY KEY,
  message_id bigint REFERENCES mail_message(id) ON DELETE CASCADE,
  filename   text,
  size       bigint,
  storage_key text,
  parsed_text_ref text
);
```

> **摘要必须缓存**（`summary` 字段）。同一封邮件不重复调用模型，这是成本控制的关键。

## 9. 任务、审计与配置

```sql
-- 替代 Celery：任务落库，APScheduler 只负责触发
CREATE TABLE job (
  id              bigserial PRIMARY KEY,
  type            text NOT NULL,       -- mail_sync / mail_summarize / doc_generate
  payload         jsonb,
  status          text DEFAULT 'pending',  -- pending/running/succeeded/failed
  attempts        int DEFAULT 0,
  max_attempts    int DEFAULT 3,
  scheduled_at    timestamptz DEFAULT now(),
  started_at      timestamptz,
  finished_at     timestamptz,
  last_error      text,
  idempotency_key text UNIQUE,         -- 幂等：防重复执行
  trace_id        text,
  created_at      timestamptz DEFAULT now()
);
CREATE INDEX ON job (status, scheduled_at);

-- 审计：只追加，不更新不删除
CREATE TABLE audit_log (
  id            bigserial PRIMARY KEY,
  trace_id      text,
  actor_id      bigint,
  actor_dept_id bigint,
  action        text NOT NULL,         -- login / kb.search / mail.summarize / doc.generate / cap.grant
  resource_type text,
  resource_id   text,
  resource_name text,
  decision      text,                  -- allow / deny
  decision_reason text,
  detail        jsonb,                 -- 脱敏后的细节（如命中的 kb_ids、引用列表）
  ip            text,
  client        text,                  -- web / desktop / h5
  created_at    timestamptz DEFAULT now()
);
CREATE INDEX ON audit_log (actor_id, created_at);
CREATE INDEX ON audit_log (action, created_at);
CREATE INDEX ON audit_log (trace_id);

CREATE TABLE sys_config (
  key        text PRIMARY KEY,
  value      jsonb NOT NULL,
  description text,
  updated_by bigint,
  updated_at timestamptz DEFAULT now()
);

CREATE TABLE notification (
  id         bigserial PRIMARY KEY,
  user_id    bigint REFERENCES "user"(id),
  type       text,
  title      text,
  body       text,
  link       text,
  channels   jsonb,                    -- 已发送渠道：{inapp:true, wecom:false}
  read_at    timestamptz,
  created_at timestamptz DEFAULT now()
);
```

## 10. 容量与索引要点

| 表 | 预估量级（500 用户 / 年） | 要点 |
|---|---|---|
| `message` | ~200 万行 | 按月分区或定期归档 |
| `ai_call_log` | ~500 万行 | **按月分区**，保留 6 个月后聚合归档 |
| `audit_log` | ~300 万行 | **按月分区**，保留期按合规要求 |
| `mail_message` | ~50 万行 | 只存摘要与元数据，**不存正文全文** |
| `job` | ~50 万行 | 定期清理已完成的旧任务 |

**分区策略**：`ai_call_log` / `audit_log` / `message` 用 PostgreSQL 原生声明式分区（按月），由 APScheduler 每月创建下月分区。

**备份**：PG 逻辑备份（`pg_dump`）每日 + WAL 归档；本地文件卷每日增量同步。详见 [09-部署与运维](./09-部署与运维.md) §6。
