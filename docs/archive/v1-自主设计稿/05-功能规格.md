# 05 · 功能规格

> 版本：v1.0 · 覆盖 MVP 三个场景的详细规格 + P1 概览 + 完整能力清单

---

## 1. 通用约定

| 项 | 约定 |
|---|---|
| 交互形态 | 会话式：左侧会话列表，中间对话流，右侧引用/工具面板 |
| 流式 | 所有模型输出走 SSE，首字延迟目标 ≤ 3s |
| 引用 | 所有知识类回答**必须**带引用卡片（文档名 + 片段 + 相似度） |
| 无依据时 | 必须明说「文档中没有找到相关内容」，**禁止编造** |
| 错误提示 | 模型不可用 → 明确告知并给降级结果，不假装成功 |
| 长任务 | 异步执行 + 进度可见 + 完成后通知，不阻塞会话 |
| 可追溯 | 每条助手消息带 `trace_id`，管理端可回放 |

## 2. 场景一：知识问答（MVP）

### 2.1 目标

员工用自然语言问公司制度、流程、规范类问题，得到**有出处**的答案。

### 2.2 用户流程

```
提问 → 场景识别（是否知识类）→ 检索 MaxKB → 组装上下文 → 生成 → 流式返回 + 引用卡片
```

### 2.3 规格

| 项 | 规格 |
|---|---|
| **输入** | 自然语言问题（≤ 2000 字）；支持追问（复用会话上下文） |
| **检索** | `Retriever.search(query, kb_ids, top_k=5)` |
| **kb_ids 来源** | **服务端**根据用户部门/角色/密级计算（红线 R4） |
| **生成** | `AIGateway.chat(scene="kb_qa")`，上下文含检索片段与来源标注 |
| **输出** | 流式答案 + 引用卡片（文档名 / 片段 / 相似度 / 来源库） |
| **无命中** | 明确回「未在知识库中找到相关内容」，并建议问题追问或联系哪个部门 |
| **追问** | 用问题改写（查询 + 最近 2 轮）后再检索，避免指代丢失 |
| **权限** | 需要能力 `kb.qa`（默认全员） |
| **不缓存** | 不缓存答案（权限上下文变化会导致串数据） |

### 2.4 异常处理

| 情况 | 行为 |
|---|---|
| MaxKB 无响应 | 返回「知识库暂时不可用」，提示稍后重试；**不降级为纯模型回答**（会产生幻觉） |
| 检索命中但分数过低 | 仍回答，但提示「未找到高度相关内容，以下仅供参考」 |
| 模型失败 | 走 fallback 链；全失败则返回检索片段原文，让用户自己看 |

### 2.5 验收标准

| # | 标准 |
|---|---|
| 1 | 20 个真实问题，**引用正确率 ≥ 85%**（引用确实支撑结论） |
| 2 | 无命中场景下**不编造**（幻觉率 ≤ 5%） |
| 3 | 越权测试：用 A 部门账号查 B 部门专属内容，**必须查不到** |
| 4 | 首字延迟 ≤ 3s，完整回答 ≤ 15s |

## 3. 场景二：邮件摘要（MVP）

### 3.1 目标

把长邮件和积压邮箱变成「一句话看懂 + 待办清单」，**只读不写**。

### 3.2 范围界定（重要）

| 做 | 不做 |
|---|---|
| 增量同步本人邮箱 | 不发送邮件 |
| 规则分类 + 优先级 | 不自动归档、不自动删除 |
| 单封摘要 + 每日汇总 | 不接入共享邮箱（P1） |
| 抽取待办与截止时间 | 不写回邮件系统 |
| 附件列表展示 | 不解析附件内容（P1） |

### 3.3 规格

| 项 | 规格 |
|---|---|
| **接入协议** | **只接公司实际的那一种**（Graph / IMAP / EWS） |
| **同步** | 首次拉最近 90 天；之后增量（deltaToken / UID）；**每 15 分钟**一次 |
| **分类** | 规则优先（发件人域 / 主题关键词 / 是否 @我 / 是否含附件）；规则未命中再走模型 |
| **优先级** | 规则 + 模型打分（0~3），排序展示 |
| **摘要** | 仅对「优先级 ≥ 1 或正文 > 500 字」的邮件调用模型；**结果落库缓存** |
| **待办抽取** | 输出 `[{what, who, due_at}]` |
| **每日汇总** | 每天 9:00 生成「昨日未读摘要 + 今日待办」，站内信通知 |
| **权限** | 需要能力 `mail.read`；**仅本人邮箱**，管理员默认不可读 |
| **成本控制** | 单用户每日模型调用上限（默认 100 次），超限只做规则分类 |

### 3.4 异常处理

| 情况 | 行为 |
|---|---|
| 邮件 API 权限不足 | 明确提示需要管理员授权，给出申请指引 |
| 同步失败 | 重试 3 次（指数退避）；失败记录到 `job.last_error` 并告警 |
| 单封摘要失败 | 该封降级为规则分类结果，不阻塞整批 |
| 邮件量异常（> 500 封/次） | 只同步元数据，摘要按需触发（防成本失控） |

### 3.5 验收标准

| # | 标准 |
|---|---|
| 1 | 试点用户邮件处理时间**下降 ≥ 30%**（自评） |
| 2 | 摘要准确率抽检 ≥ 90%（10 封人工核对） |
| 3 | **零误发**（本阶段无发送能力，权限上也不可能） |
| 4 | 单用户日模型成本 ≤ 设定上限 |

## 4. 场景三：文档生成（MVP）

### 4.1 目标

把零散材料一键变成可交付的 Word 文档（周报 / 汇报 / 方案初稿）。

### 4.2 规格

| 项 | 规格 |
|---|---|
| **材料输入** | 上传文件（docx/xlsx/pdf/md/txt）、粘贴文本、引用历史会话、引用知识库片段 |
| **解析** | python-docx / openpyxl / python-pptx / PyMuPDF 提取文本与表格 |
| **模板** | 内置「周报」「月报」「方案」三个模板（P1 做模板中心） |
| **生成** | `AIGateway.chat(scene="doc_gen")`，按模板结构生成 Markdown |
| **产出** | ① 网页预览 ② 导出 `.docx`（python-docx）③ 导出 `.md` |
| **落盘** | `storage.save()` → `attachment` 记录 → 下载链接（带权限校验） |
| **权限** | 需要能力 `doc.generate`（默认全员）；导出需 `doc.export` |
| **审计** | 记录：生成了什么、基于哪些材料、谁下载了 |
| **异步** | 材料 > 5 份或生成 > 30s 时转异步任务，完成后通知 |

### 4.3 异常处理

| 情况 | 行为 |
|---|---|
| 材料解析失败 | 明确标出哪个文件失败，其余继续 |
| 材料超长（> 模型上下文） | 先分块摘要再汇总生成（map-reduce），并告知用户 |
| 生成超时 | 保留已完成部分，允许重试 |
| 导出失败 | 保留 Markdown，提示可复制 |

### 4.4 验收标准

| # | 标准 |
|---|---|
| 1 | 一份周报产出时间从约 60 分钟降到 **10 分钟内** |
| 2 | 导出 docx 在 Office / WPS 中**格式正常**（标题层级、列表、表格） |
| 3 | 材料解析成功率 ≥ 95%（常见格式样本集） |
| 4 | 生成内容**不出现材料中不存在的事实**（抽检） |

## 5. P1 场景概览（验证通过后做）

| 场景 | 关键点 | 依赖 |

| **待办中心** | 邮件待办 + 会话待办统一视图 | — |
| **日程会议** | 查空闲、约会议、会前材料 | 日历 API |
| **模板中心** | 公司标准模板集中管理与套用 | — |
| **工作流与定时** | 定时汇总、事件触发 | — |
