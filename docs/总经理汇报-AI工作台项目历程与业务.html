一页摘要

企业 AI 工作台已经从"一个能对话的 AI 客户端"成长为公司内部统一的 AI 能力底座： 把外部与自建模型收敛到一个受管控的网关，把员工身份、权限、额度、数据边界集中在平台侧， 并在员工真正干活的三个场景（对话问答、任务执行、邮件与文件处理）上提供可审计、可审批、可追溯的落地能力。

当前已交付 桌面客户端（12 个功能模块）、管理后台（21 个管理页面）、 企业微信移动端（免登问答） 三个端，以及支撑它们的 150 个平台接口 与 32 次数据库版本演进。代码规模约 7.3 万行（Python 65,810 行 + 前端 7,523 行）， 全部纳入自动化质量门禁：当前 377 项服务端测试 + 100 项前端测试全绿。

项目历程：从对话工具到公司 AI 底座

第 2 页 / 共 7 页

整个建设过程可以按能力的纵深分成五个阶段。下面每一阶段都对应数据库中真实存在的版本演进记录 （迁移编号 0001 → 0032），不是规划口径，而是已落库、已在环境上运行的能力。

  • 阶段一 · 打通链路：让 AI 能对话、能被管起来 建立平台服务端底座：统一模型网关（把外部模型与自建模型收敛为"逻辑模型 → 实际模型"的路由）、 用户与角色体系、企业微信身份接入；同时交付桌面客户端的对话能力（流式回答、会话管理、来源引用）。 数据库从 0001 初始架构 演进到 0003 会话状态、0007 消息反馈。
  • 阶段二 · 建立治理：把"能用"变成"敢用" 补齐企业采用 AI 的前置条件——0004 治理、0008 配额策略、 0015 模型调用记录、0020 用量对账、0022 告警投递、 0009 提示词复核。此时公司可以回答四个关键问题：谁在用、用了多少、花了多少钱、 数据流出去了什么；并能对模型、额度、访问范围做集中管控。
  • 阶段三 · 进入真实业务：AI 开始"干活" 从"问答"走向"执行"：任务中心（0026 云端任务、0028 智能体计划）、 文件与成果物（导入、安全扫描、哈希登记、模板与批注）、邮件助手 （0025 服务端邮箱接入、0029 邮件分组模板）、知识库检索、 企业数据连接器（0006 企业连接器、0017 数据库连接器）、 受审批的业务写操作（0027 业务动作）。
  • 阶段四 · 三端互通与可交付 补齐管理后台（21 个页面）与企业微信移动端免登问答（0030 会话同步）， 建立客户端发布机制（签名清单、稳定／试点／开发三环灰度，0018 扩展灰度、 0012 客户端发布），并把部署收敛为 Docker Compose + 1Panel 的标准形态， 具备 staging 与 production 双环境。
  • 阶段五 · 质量加固与三端一致性（最近一轮集中投入） 在功能面已经铺开之后，把注意力转向"长期可靠"。完成：门禁确定性改造（消除被自动重跑掩盖的偶发失败）、 三处事务原子性缺陷修复（其中一处会把已成功发送的定时邮件误标为失败）、 三端语义色与状态标签口径统一、可访问性对比度达标、破坏性操作视觉区分、 Web 端样式静默丢失修复。所有改动均以"自动化门禁全绿 + 界面像素对照"收尾。

三项贯穿全局的设计决定

① 模型不直连，一律经过公司网关

  • 员工端不持有任何模型密钥，密钥只在服务端。
  • 模型可随时替换／降级，员工无感。
  • 每次调用都留痕：逻辑模型、实际模型、耗时、token、成本。

② 数据分级由公司定义边界

  • 模型按"允许处理的数据等级"配置，机密级以上默认不出内网。
  • 邮件正文在本地做敏感内容检查。
  • 知识库检索以公司自建 MaxKB 为组件，权限判定仍在公司侧。

③ 涉及公司数据的动作要人确认

  • 任务执行前生成可复核的执行计划，逐步审批。
  • 企业数据的写入操作必须提交申请 → 审批 → 执行，全程可对账。
  • 成果物登记来源、模板与哈希，可校验未被篡改。

④ 一套设计规范覆盖三个端

  • 颜色、圆角、字号、间距、控件尺寸来自同一份 token 定义。
  • 由脚本自动导出到两个前端，并有同步校验，不会各自漂移。
  • 状态色语义统一：正常／需注意／失败／未知四档，三端一致。

已实现业务（一）：员工每天会用到什么

第 4 页 / 共 7 页

AI 对话 已上线

  • 多模型统一入口：员工不需要知道背后是哪个模型。
  • 流式回答、会话分支、收藏与标签、全文搜索、整段导出。
  • 回答标注来源引用，可回溯到文件或知识库条目。
  • 逐条反馈（有用／无用／报告问题）回流到管理端。

任务中心 已上线

  • 用一句自然语言描述目标，先生成可复核的执行计划再执行。
  • 本机执行与公司云端执行边界清晰，涉及公司数据默认走审批。
  • 产出 DOCX／XLSX／PPTX／PDF 成果物，附带格式校验与哈希登记。
  • 支持定时计划、取消、失败重试，进度与步骤全程可见。

文件与成果物 已上线

  • 文件只复制到受控工作区，解析成功后才能被引用。
  • 导入即做安全扫描、OCR、大文件分块。
  • 版本历史、对比、预览与批注、公司模板库。
  • 成果物记录来源、模板、SHA-256 与校验结论。

邮件助手 已上线

  • IMAP／SMTP 多账户收发，支持服务端邮箱统一接入。
  • 智能视图：未读／星标／含附件／今天／近 7 天／需回复。
  • 分类、标签、规则引擎自动归档（按发件域、主题等条件）。
  • 签名与分组模板、定时发送、草稿、联系人、会话线索归并。
  • 发送前做 DLP 敏感内容检查与治理策略校验。

知识库 已上线

  • 对接公司自建 MaxKB，员工提问返回带引用的答案。
  • 权限判定保留在公司服务端，知识库本身只作为检索组件。

企业应用与连接器 已上线

  • 只读查询：管理员预先定义 SQL 与参数白名单，员工按授权范围取数。
  • 业务写操作：提交申请 → 审批 → 执行，幂等且可对账。
  • 连接器主机走精确白名单，凭据不下发到客户端。

会议与翻译 已上线

  • 企业微信会议查询与日程查看。
  • 文档／内容翻译能力。

应用与插件／设置与帮助 已上线

  • 内置扩展与已复核签名的外部扩展，权限明细可见可管。
  • MCP 工具调用留痕；扩展可被远程停用或撤权。
  • 模型连接、个人偏好、通知中心、更新说明与一键诊断。

平台侧已经落地的关键机制

统一模型网关

  • 逻辑模型 → 实际模型的映射与故障降级。
  • 按数据等级限制可用模型，越权请求直接拒绝。
  • 额度策略支持提醒与降级两档处置。

身份与目录

  • 企业微信扫码与静默授权登录，员工无需新账号。
  • 部门目录快照同步，离职／调岗可自动失效。
  • 角色分层：管理员／审计员／普通员工，最小权限。

可审计

  • 模型调用、额度变更、权限调整、审批动作全部留痕。
  • 审计日志支持按条件检索与导出（含表格注入防护）。
  • 用量与账单可对账，差异单独记录。

可运维

  • 签名 Webhook 告警通道 + 投递台账（可查是否送达、重试几次）。
  • 客户端发布走签名清单与三环灰度，可强制更新。
  • 健康检查、指标、遥测与崩溃上报。
一句话说明治理闭环： 员工在桌面上做任何涉及公司数据的动作，都会在平台留下"计划 → 审批 → 执行 → 结果 → 成本"的完整链条； 管理员与审计员看到的是同一份事实。

需要公司层面确认的四件事

以下四项属于部署环境或外部系统的事实，代码层面无法单方面判定，需要运维或企业微信管理员配合确认后，才能决定是否需要改动：

  • 指标接口的对外暴露范围——该接口无认证，会暴露内部接口清单；需要确认反向代理是否已屏蔽。
  • 企业微信内置浏览器对跨站静默授权的行为——决定移动端免登链路是否需要补一层发起方校验。
  • 生产环境会议服务的实际提供方配置——若仍为内置模拟实现，会议数据将不按用户隔离。
  • 会议上游服务对路径参数的处理方式——决定是否需要补充参数校验。

结论

企业 AI 工作台的功能骨架已经完整：员工端三个场景（对话、任务、邮件与文件）可用，公司侧 "模型—额度—权限—数据边界—审计—成本"六个管控面齐备，三端互通与灰度发布链路已验证。 项目当前的状态是功能面铺开、可靠性收口：最近一轮的集中加固把交付质量从 "界面全绿"推进到"严格模式零失败"，并且把三端的视觉与语义口径真正统一到了一份设计规范上。

建议按上表顺序推进，其中移动端补齐与对话框界面回归覆盖两项 投入最小、收益最直接，可优先安排；其余四项需要公司先确认环境事实再决定是否投入。
